# 魈嘶的学生端 Agent 开发文件

你是魈嘶的开发助手。用户是首次参与完整协作的开发者，解释步骤用普通中文；每次交付一个能打开、能点击、能核实的结果。不要只输出建议或让用户自行补全代码。

## 所有权

可修改 apps/mobile/src/modules/student/ 内的实现、局部样式、测试、说明，以及本人执行方案和本人进度。你不是独自在代码库工作，不得撤销别人的改动。不修改 contracts、公共依赖与锁文件、后端、档口或管理端，不写队友进度。需要公共调整时写出具体字段或错误及页面影响，交 spcuteag 统一处理。

## 页面与行为

先实现菜单和数量选择、时段和用餐方式、确认下单、订单列表和详情，复用详情展示取餐码、取消、退款和延迟结果，不扩张成大量页面。

用餐方式必须显式选择 DINE_IN 或 TAKEAWAY。金额使用服务端返回值，单位为分；本地预估不能成为支付或下单结果的依据。下单包含一次操作的 requestId，网络失败重试复用原值；明确结束或主动开始另一笔订单才生成新值。重复点按钮只禁用按钮还不够，需要配合服务端去重。超时后显示结果待确认并查询或重试同一请求，不能提示“失败后请重新下单”导致重复。

状态、退款与取消申请分别按契约展示。取消申请不等于取消成功，不能预先把订单隐藏。接口报错显示可理解原因，失败不返回假成功。不另造待付款流程，首版下单和模拟付款合并。
首版用餐方式变更由学生线下联系档口确认；详情提供明确说明，随后读取档口更新结果。不要制作没有对应接口的“变更申请已提交”按钮。

## 堂食参考与定位

展示服务端返回的所选时段参考、当前参考、更新时间、依据与演示标记。异步切换时段需丢弃旧时段迟到响应，未知、过期、加载失败不显示为零人或有座位。拥挤提醒不能禁用堂食或自动改外带。

只在主动点击后解释用途并请求一次定位，不在页面加载时索取权限或持续追踪。范围和误差判断采用 spcuteag 给定规则/示例；公共定位方法获取的坐标仅在设备内存中计算，禁止上传、持久化、写日志或出现在错误截图中。只发送契约允许的范围判断，不发送任意用户标识；以登录身份关联。拒绝或失败继续下单。提供清除本人位置记录入口，并解释不能因此清除订单本身。

真实手机定位应使用符合平台权限要求的实际访问环境；环境不支持时记录阻碍，不能用模拟值冒充真实定位。目标食堂边界准确性单独现场验证。

## 验证和交接

对重复下单、失败重试、取消申请展示、切换时段响应竞争、拒绝定位不阻塞以及失败不回退假数据补针对性测试。只运行实际存在的项目命令，并记录命令和结果。用两台手机做一次真正共同操作，标明真实服务还是样例；真实定位与食堂现场验证分别记录。行为代码完成后按根规则独立复核。

交接必须含：文件范围、提交/PR、契约版本、启动方法、实际测试、页面操作路径、剩余样例/未完成点、需要 backend 或 merchant 的具体配合；写入本人 progress.md。卡住先最小复现，不全库扫描或重写项目。

## 单 APK 新约定

本轮只做一个安卓应用。你的页面是 apps/mobile 中的一个模块，不是独立网站或独立 APK。进入模块前读 apps/mobile/AGENTS.md；共享登录、角色入口、请求封装、定位适配、依赖及安卓打包由 spcuteag 维护。禁止自行创建另一个移动项目、另装一套框架或改公共入口。

第 1 天你必须在 spcuteag 提供的统一应用中打开自己的样例页面，并参与真实手机安装检查。第 2—3 天将页面接到真实公共服务。第 4—5 天用同一份 APK 验收并写清安装包版本；浏览器验证只作为开发辅助，不能替代安卓实机验收。拒绝定位后仍能完成核心流程。

APK 中定位走公共的一次性定位方法；浏览器开发环境使用对应适配，模块不直接引入插件或配置权限。公共方法在设备内完成坐标与误差判断，只把范围判断交给模块及服务端，禁止模块记录或上传精确位置。公共服务地址由 spcuteag 配置，手机不能使用开发电脑的 localhost 地址。
